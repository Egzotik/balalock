# POSTMORTEM — mod для Deadlock

Экран разбора матча прямо в игре: farming, драки, объективы, itemization, сравнение с
лобби и тоталы команд. Открывается по кнопке, а не встроен в интерфейс игры.

**Статус: фаза 1 завершена, сборка работает. Требуется прогон в игре.**

Собранный аддон: `build/pak01_dir.vpk` (184 688 байт, 11 ассетов, проверено содержимым).

---

## Что это

Мод для Deadlock (Valve, Source 2, Panorama). Переопределяет два нативных layout-файла
и добавляет в них кнопку; по нажатию открывается собственный полноэкранный экран.

Оригинальный мод-модель — `POSTMORTEM` от Tripod110 (GameBanana 703342), просуществовавший
4 часа 12 августа 2026 и удалённый за нарушение политики об AI-контенте. Экрана как такового
уже нет; функционал восстановлен по его скриншоту и по нативным биндингам самой игры.

## Входы

| Где | Файл | Зачем |
|---|---|---|
| Страница профиля, рядом с «View All» | `panorama/layout/citadel_db_page_profile.xml` | Список своих матчей + career-статы, выбор матча |
| Пост-матч экран, рядом с REPLAY | `panorama/layout/post_game/citadel_db_page_post_game_new.xml` | Разбор открытого матча |

Поток: **профиль → список матчей → «open» → игра сама открывает полное табло этого матча →
наш второй хост показывает разбор.**

**Главное открытие, изменившее проект.** Клик по «View Details» у блока истории матчей
открывает полное табло **произвольного прошлого матча**. Проверено в игре на сборке
25763945. Значит и история матчей, и полная статистика по любому из них берутся из самой
игры — **без сети, без `api.deadlock-api.com` и без CEF-моста**. Мы просто нажимаем
собственную кнопку игры через `$.DispatchEvent("Activated", panel, "mouse")` — приём из
работающего мода Commend Everyone.

**Почему профиль, а не главная страница.** Главная страница не содержит ни данных, ни
истории — кнопка там могла бы показать только пустую оболочку. Профиль содержит оба
источника: `{d:player_stats_state}` (career) и `{d:match_history_state}` (своя история).

**Почему не футер дашборда.** `citadel_dashboard_footer_bar.xml` выглядел очевидным
кандидатом, но его корень `CitadelFooterBar` закреплён на `height: 28px`. Оверлей строится
через `$.CreatePanel` и должен занять весь экран; внутри 28-пиксельного корня он либо
обрежется, либо окажется в нерабочей области. Отложено: `docs/COMPAT.md`, раздел 7.

## Правила, которые нельзя нарушать

Обе правки — **только аддитивные**. Известные краши вида

```
FATAL ERROR: Unable to find child 'Team1Screen' in layout file
'panorama\layout\post_game\citadel_db_page_post_game_new.xml'
```

возникают, когда мод **вырезает** ванильного потомка, которого C++ ищет по имени. Мы не
вырезаем ничего. Второе правило: на каждом `<include>` сохраняется суффикс `_c` — игра
резолвит только имена скомпилированных ассетов.

## Сборка

Нужно: **Reduced CSDK 12** в `C:\Reduced_CSDK_12` и Python с пакетом `vpk`.

```powershell
# один раз: заглушки для ассетов, на которые ссылается ванильный layout
powershell -ExecutionPolicy Bypass -File tools\seed_missing_assets.ps1

# сборка
powershell -ExecutionPolicy Bypass -File tools\build_mod.ps1 -Clean
```

Сборщик прогоняет шесть шагов с проверкой на каждом:

1. **[2a] линтер пространства JS** — ловит ошибку, которая стоила пять
прогонов в пяти сборках (Node нет, поэтому статического линтера нем есть)
2. **[2b] тесты движка анализа** — 117 проверок медианы, рангов, участия в убийствах и форматирования чисел
3. **[2c] проверка палиты** — компилятор CSS молчит про неизвестные имена цветов, игра протестует лишь накаждый

1. stage — `panorama\` копируется в `content\citadel_addons\postmortem\`
2. compile — `game\bin_cs2\win64\resourcecompiler.exe`
3. pack — `vpk.new(dir).save(out)`, только поддерево `panorama\`
4. verify — перечитывает VPK и проверяет записи

**Используется именно `bin_cs2`.** Наборы `bin` и `bin_tools` падают с
`ParticleFloatType_t / Mismatch - Member Count`, `bin_server` — с тем же, но вторым модулем
`animationsystem.dll`. На сборке 25763945 компилируется только `bin_cs2`.

## Установка

**Deadlock Mod Manager → Mods Library → Add Local Mod** → перетащить
`build\pak01_dir.vpk` → заполнить имя (обязательно только оно) → **Manage Files** →
выбрать файл → **Apply** → **Enable** → закрыть игру → **Launch modged**.

Публиковать на GameBanana до проверки в игре не нужно: локальные моды DMM не проверяются на
обновления, но для разработки это правильный путь.

## Что делать дальше

**Прогнать в игре и прислать лог.** Процедура — `docs/RUNBOOK.md`.

Что проверяем по приоритету:

1. Кнопка на странице про��иля видна и открывает список матчей.
2. `open` на матче уводит на полное табло, кнопка рядом с REPLAY открывает разбор.
3. В логе появляются `[PM-DATA] post-game match <id>: N players` — это значит, что
   читаются настоящие цифры, а не пустые заглушки.
4. Геометрия оверлея: строка `[PM] open vis=... overlay=WxH ...`.

CEF-мост (`pm_net.js`) и пробник оставлены в сборке, но **выключены по умолчанию** и
больше не в критическом пути: он нужен только для Counter Buys и FAM в полном виде —
двух вещей, которых в игре просто нет.

## Данные

**Всё основное — из самой игры, без сети.**

| Что | Откуда | Точность |
|---|---|---|
| Career: игры, победы, last hits, denies, комменты | `{d:player_stats_state}` | точная |
| Свой список матчей: герой, исход, длительность, дата, нетворс | `{d:match_history_state}` → `CitadelMatchHistoryBlockLarge` | точная |
| Полная статистика матча по всем 10 игрокам | `CitadelPostGameScoreboardNew` на пост-матч экране | KDA — точная, души/урон/лечение — форматированные (`12.3k`) |

Форматированные значения парсятся в числа, но с потерей: около сотни. Для медианы лобби и
места в нём это годится, для чего-то точнее — нет. Непрочитанное значение становится
`null`, а не нулём: выдуманный ноль показал бы игрока, который ничего не сделал.

`api.deadlock-api.com` может понадобиться только для Counter Buys и FAM в полном виде —
этого в игре нет. Транспорт выключен по умолчанию.
