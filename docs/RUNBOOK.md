# RUNBOOK — проверка фазы 1 в игре

Это единственный шаг, который нельзя выполнить без игрока. Всё остальное собрано и
проверено: аддон компилируется (9 ассетов, 0 ошибок), упакован в VPK, содержимое
проверено перечитыванием архива.

Ниже — ровно то, что нужно сделать, и что означает каждый результат.

---

## 0. Подготовка


## 1. Установка

1. Полностью закрыть Deadlock.
2. Deadlock Mod Manager → **Mods Library** → **Add Local Mod**.
3. Перетащить `build\pak01_dir.vpk`.
4. Заполнить имя (единственное обязательное поле), выбрать категорию.
5. Добавить в библиотеку → **Manage Files** → отметить файл → **Apply**.
6. **Enable** в Mods Library.
7. **Launch modged**. Как и для любого сетевого мода, игра спросит Match ID / SteamID —
   это отдельный шаг DMM, не относящийся к нашему моду.

## 2. Лог

Открыть консоль игры и включить фильтр, иначе буфер ~3 МБ вытеснит результат:

```

```

Файл лога: `steamapps\common\Deadlock\game\citadel\console.log`

## 2b. Что было подтверждено в сборке 1

Что доказано в прогоне и работает без изменений:

- `FATAL ERROR` / `Unable to find child` в логе нет; переопределение post-game layout работает
- карусель вкладок целам, страница рисуется
- кнопка POSTMORTEM видна и кликается
- `Button_PM_PostGameButton_onactivate` в логе

Было три бага в самой сборке 1. Сборка 2 чинит три вещи: общение пространства (`globalThis`),
невалидные цвета в CSS, и отсутствие в логе из исключения в `boot()`.
Все три исправлены, см. раздел 0 в `docs/COMPAT.md`.

## 2c. Сборка 3: главное изменение

Симптом из сборки 2: кнопка кликалась, оверлей открывался, но ничего не было видно, а ESC приходился два раза.

Второе ESC было подтверждение: первый ESC закрывает оверлей, второй выходит со страницы. То есть объект создавался, но в 0x0.

Исправлено два причины:

1. Геометрия берётся из родителя и пишется в пикселёлы `панелью`. Раньше `100%` по родителю и дефолт `visibility: collapse`.
2. Проверка таблицевого размера теперь отложена на кадр кадр, а не в селективный виджет.

Теперь `pm_core.js` измерияет родитель, пишет явные пиксели, записывает геометрию в пикселях и больше не висит наложении в одном идопоток.

Ожидаемый лог для следющего обрщения:

```
[PM] host geometry 1920x1080 id=CitadelPostGameNew type=CitadelPostGameNew
[PM] open vis=visible overlay=1920x1080 backdrop=1920x1080 frame=1770x993 children=2 xIndex=10000 parent=CitadelPostGameNew
```

Строка `open` даёт всю ѐасторию за одним прогона: размер, рисунок, число детей, родитель. Если там `overlay=0x0` или `vis=collapse` — вот и будет появится в следующем коде.

## 3. Проверка входов

### 3.1 Страница профиля

Кнопка POSTMORTEM рядом с иконкой View All.

| Что видим | Вывод |
|---|---|
| Кнопка **POSTMORTEM** рядом с **View All**, над Discord/рекомендациями | хост A работает, оверлей имеет место, совместимость пройдена |
| Кнопки нет | см. раздел «Диагностика неудач» |
| Кнопка есть, но сереет/пропадает при наведении | хост A работает, но `pm_button.vcss` не применился |

### 3.2 Пост-матч

Сыграть или дождаться любого матча. На экране результата — кнопка **POSTMORTEM** слева от
REPLAY.

| Что видим | Вывод |
|---|---|
| Кнопка есть | хост B работает |
| Кнопки нет, футер в целом виден | не сработал `ProgressState_None/Completed`; см. `docs/COMPAT.md` |
| **Краш с `FATAL ERROR: Unable to find child`** | стоп, читать `docs/COMPAT.md`, раздел «Аварийный откат» |

Важно: вкладки карусели (Team 1 / Team 2 / Scoreboard / Graphs) должны листаться
стрелками как обычно. Это главная проверка аддитивности — если мы что-то сломали в
структуре, карусель поведёт себя иначе.

### 3.3 Открытие экрана и выбор матча

На странице профиля нажать POSTMORTEM.

Ожидается экран со списком career-статов и списком своих матчей. Заголовки
записывается как разбиение по всем восми матчам.

Кликнуть `open` на любой строке.

Ожидается: **/игра сама перейдёт на полное табло этого
матчаа**. Нас второй хост тот же делает, ното без нашего кода.

### 3.4 Разбор матча на пост-матч экране

Нажать POSTMORTEM. Ожидается: карточка героя, K/D/A, четыре метрики
против самого и себя в лобби.

Влоге должно появиться:

```
[PM-DATA] post-game match 111983018: 10 players
[PM-DATA] career 240 games, 132 won, winrate 55%, lastHits 120433, denies 8122
[PM-DATA] history: 12 match blocks, first: Grey Talon Loss 32:14 8.3k
```

Если вывод `post-game match ...: 0 players` или
`career ... no-player-rows` — значение не читается, а оверлей неверный.

### 3.5 Геометрия оверлея

Строка `открытие экрана` должна дать всю геометрию за один открытие:

```
[PM] host geometry 1920x1080 id=CitadelProfilePage type=CitadelProfilePage
[PM] open vis=visible overlay=1920x1080 backdrop=1920x1080 frame=1770x993 children=2 xIndex=10000 parent=CitadelProfilePage
```

Если `overlay=0x0` или `vis=collapse` — геометрия не применилась
и во следующем коде всё есть.

### 3.6 Закрытие

Кнопка Close или ESC.

## 4. Пробник транспорта (ключевой вопрос фазы)

**POSTMORTEM → Diagnostics → Run probe.** Ждать до 12 секунд.

Пробник отвечает на четыре вопроса, и это единственная причина, по которой он в сборке.

### Ожидаемый полный успех

```
Q1 createPanel OK, paneltype=CitadelHTMLPanel
Q2 page loaded and pushed. replies=alive,types,len64,...
Q3 lengths arrived: {"len64": 64, "len1024": 1024, "len4096": 4096, "len8192": 4096}
Q4 api.deadlock-api.com -> ok 200
VERDICT q4-ok: transport works AND the API is reachable from here.
```

Значение `len8192: 4096` — это не баг, а ожидаемое поведение: канал молча режет всё
длиннее 4096 символов. Именно поэтому большие данные придётся читать по частям.

### Разбор неудачных вердиктов

| Вердикт | Что значит | Что делать |
|---|---|---|
| `q1-fail` | в контексте дашборда не создаётся `CitadelHTMLPanel` | API-часть недостижима в этом хосте. Играемся без неё, отчёт об ошибке — сюда |
| `q2-fail` | панель создалась, страница не грузится | проверить `BRIDGE_URL` в `pm_net.js`; при пустом значении пробник всё равно должен дойти до `alive` |
| `q3-only` | транспорт работает, API не ответил | поставить прокси на `BRIDGE_URL` (закрывает CORS и старый TLS) |
| `q4-cors-or-tls` | API ответил ошибкой | смотреть текст ошибки: `CORS` — нужен прокси, `Failed to fetch` — вероятно старый TLS CEF |

Отдельно важно: если `alive` не пришёл вовсе, а страница при этом точно грузилась —
искать в логе `page script did NOT reach its end`. Это признак того, что скрипт страницы
упал на первом же обращении, а не того, что транспорта нет.

## 5. Замер кадра

Отдельно замерить базовый уровень **без** CEF: чужой пробник измерил 1.2–2.2% кадров
длиннее 17.5 мс при живом CEF, но базовый уровень без CEF не измерял никто. Если при
открытом экране появилась заметная просадка кадров — это важно знать до публикации.

## 6. Диагностика неудач

Первое, что нужно: скопировать сюда выгрузку лога.

```
con_filter_enable 1 ; con_filter_text PM
```

из `console.log` плюс описание: что нажали, что ожидали, что увидели.

Ключевые строки, которые стоит искать глазами:

| Строка | Значение |
|---|---|
| `[PM] loaded in an unexpected context; staying inert` | скрипт попал не в тот XML-контекст — хост-детектор не узнал корень |
| `[PM] layout mismatch; button stays hidden` | не хватает ванильного потомка, перечислить в `MISSING[...]` |
| `[PM] host is too small for the overlay` | контекст меньше 600×400, оверлей негде рисовать |
| `[PM] entry button #PM_... not found in our layout copy` | наша правка layout не попала в сборку — пересобрать |
| `[PM] match id: <id>` | Match ID читается, значит доступ к постусматчевым данным есть |

## 7. Аварийный откат

Если пост-матч экран перестал открываться вообще:

1. Mods Library → **Disable all mods** → перезапуск игры.
2. Если помогло — виноват наш мод, читать `docs/COMPAT.md`.
3. Удалить аддон через Mods Library, если он мешает.

Откат без снятия: убрать `citadel_addons\postmortem` из CSDK и пересобрать с пустой
директорией `panorama\layout\post_game\` — но проще отключить в DMM.

### Проверка тела в логе

### Проверка

Пользом колеса, горизонтальной скроллбарба быть не должна:
раздел по вертикали, и полоса ширины не уезжаются за правый край.

```
[PM] scroll body=1766x993 acceptsOffset=yes hittest=true
```

`acceptsOffset=no` — панель не принимает смещения (колесо меньше немоговидотуго),
и колесо не должно: скроллбар появился только из-за из-0437а `fill-parent-flow` с отступами.
`acceptsOffset=yes` — прокрутка работает.

```
[PM-DATA] post-game units: souls="42" u="..." hdmg="30" u="..." ...
[PM-DATA] post-game match <id>: 12 players local=1 duration=1560 | sample soul=42000 kda=13/2/18 ...
```

Самая важная строка — единственный диагност об масштабе весь экран. Если внимани остался пустым:

* `local=0` — метка «свой игрок» переехала. Откройте вкладку «Таблица» и нажмите кнопку.
* `sample soul=` пустой — значения не пришли.
* `duration=null` — длительность матча не найдена, перминутной ноги нет, разбор идёт по итогам.
