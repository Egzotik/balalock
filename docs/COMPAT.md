# COMPAT — что ломается при обновлениях игры

Этот мод переопределяет два нативных файла, поэтому он по определению зависит от версии
игры. Документ описывает, что именно ломается, как это обнаружить и что делать.

Ориентир сборки, на которой всё проверялось: **25763945**, первый прогон в игре
**10.08.2026 03:41**.

---

## 0. Факты о платформе, измеренные в игре

Не из документации, а из лога первого прогона. Каждая ловушка стоила реального круга
отладки, поэтому вынесена сюда, а не забыта.

### 0.0 Главная ошибка: слот модуля никогда не создан

Следыющие пять прогонов в одной и тот же баг в одном коде. Сборки 1"5
грузили один и тот же дефект: `pm_compat.js` и `pm_probe.js` писали

```js
PM.Compat.check = checkHost;    // TypeError: присваивание в унифицированный undefined
```

Поскольку слот `PM.Compat` никто не создано, весь файл целиком пропускался
при загрузке Panorama. Единственный символ в игровом логе:

```
Uncaught TypeError: Cannot set properties of undefined (setting 'check')
```

Почему это было неведомо: `pm_data.js` и `pm_net.js` целиком работали, потому что
они делают `PM.Data = { ... }` целиком. Из-за этого появилось со спорным общением
напрямую, а с отсутствием объекта. Следствие было сделано
не самое по сути — пропускали после исправления, которая не переанестровала.

Исправление:

```js
PM.Compat = { check: checkHost, describe: describe, ... };   // создаёт слот
```

А проверка появилась теперь шаг [2a] в `build_mod.ps1`.
Она ловит только виды вольных записей по шаблону `PM.Slot.field =`.

### 0.06 Ловушка: `LocalPlayerIdentifier`

В ванильной разметке этот элемент объявлен **в каждой строке**, а игра
просто его сворачивает только на своей. Поетому наличие его наличия
работает у всех двенадцати, и отчёт первый игрок табло.

В сборке 7 отчёт был добавлен
`isLocal: row.BHasClass('IsLocalPlayer') || !!findDeep(row, 'LocalPlayerIdentifier')`,
и всё строки считались вот своими. Итог был **Dynamo** в матче за Drifter.

Правило выводается настоящий правило: если ни одной строке не помечено как своя — анализирует страна, если класс.

### 0.08 Главное: у Panorama ОДИН общий глобальный пространстранство

Все скрипты, загруженные в один контекст панели, делят **одну и тот же глобальное окружение**. Два файла, оба объявили `function valid()`, — это не две функции, а одна функция, перезаписанная последней. Никто не пишет.

В этом проекте это случилось три раза:

| Имя | Где | Последствие |
|---|---|---|
| `AWARD_CLASSES` | `pm_data.js` — список **имён**, `pm_analysis.js` — список **пар** | все награды команды молча выгодили пустыми |
| `state` | `pm_net.js`, `pm_core.js` | `pm_net` читал бы своё состояние оверлей, как только у наложеного состояние |
| `say` | `pm_data.js`, `pm_net.js`, `pm_probe.js` | в лог с тегом подписывалась не тот тег, а чужой из них |
| `valid`, `childById` | `pm_compat.js`, `pm_data.js` | семантика семантика, поэтому шанс оботался |

Объявление: `valid` -> `dataValid` / `compatValid`, `childById` -> `dataChildById` /
`compatChildById`, `say` -> `dataLog` / `netLog` / `probeLog`, `state` -> `netState`,
`AWARD_CLASSES` -> `AWARD_CLASS_NAMES` в `pm_data.js`. Ключи экспорта остался как ключи.

`tools/check_js_globals.py`, шаг [2b2a]: 116 имён в модулях, каждое в ровно одного файла.

### 0.085 Третье вид одной причины: ключ экспорта именовался вместе с функцией

```js
PM.Compat = { ..., childById: compatChildById, compatValid: compatValid };  // ключ перееменован
```

`detectHost()` вызывал `PM.Compat.valid` — это `undefined` — и падал. `boot()` умер
до до того, как успела поставить `state.host`.

Оверлей при этом появился, потому что `openOverlay()` собирает его
леньо по кнопке. Итог пользователь увидел всю скрину — заголовки,
каждый заголовок столец — но без данных, и в логе одна
строка `Cannot read property of undefined`.

`tools/check_js_exports.py`, шаг [2b2b]: 37 ссылок межмодулями сверяются с 6 опубликованными модулями.

Ополня это инцидентна в единственный код: `boot()` больше
не падает в `try`, а `refresh()` при `null`-host пишет в лог и записывает проблему.
Пустой экран, который выглядит как готовый.

### 0.07 Главная ошибка: класс в слоте `id`

Хаблону весь экран строится одной вызов:

```js
function make(type, parent, id, cls)
```

А правилсь было везди по аргументу в слоте `id`:

```js
make('Label', row, 'PMCell name', '')   // id = "PMCell name", класса нет
```

Лабель получил `id` и не получила ни одного класса, поэтому ни одно правило CSS-правило её не сработало.

Самое ошибка стоиль то я и в слоте `id` — и там ошибка сработала, потому что верх экрана выглядела нормально, а всю таблицы под ней склиплись.

Симптом:
`налоза` стал `undefined` вместо заголовка колонки, колонки слиплись друг на друг друг,
`ФАРМ1.4 souls/min` без пробела между тегеми.

Ни чего не выше теста, ни одного линся в живом логе — `tools/check_panel_slots.py`, шаг [2b3].

### 0.07 ES3: висящая запятая в массиве или файле

Panorama разрешает тейскить выше ES3. Однако тестами (`tools/test_analysis.js`)
под разбираемым парсера JScript — строгие оба отвергают
три вещи вещений ошибки:

* `висящая запятая` перед `}` или `]` — терпевающая выборка. Panorama создает пустой `undefined` в конец массива, и любой цикл по нему падает.
  В `METRICS` именно это сломало седьмым элементом, и оверлей падал бы при открытии на всходе.
* **Зарезервированные слова ES3** (`close`, `open`, `class`) нельзя как ключ в объекте — переименовано в `closeButton`.

Источник — два ограничения в пользовательской синтаксисе; рассуждения, и именно более строгое теста превращает, что источник строгее.

### 0.1 `globalThis` — НЕ общий между файлами `.vjs_c`

Каждый скомпилированный скрипт получает **собственный** `globalThis`. Модуль, повешенный на
`globalThis.PM`, в следующем файле — уже другой объект:

```
JS Exception! *** Skipping rest of script ***
pm_compat.js line:143  >> PM.Compat.check = checkHost;
Uncaught TypeError: Cannot set properties of undefined (setting 'check')
```

`$` — общий объект для всех скриптов одного панельного контекста. Поэтому
пространство имён живёт на `$.PM`, ровно как `$.MG` у мода DL Arcade.

При этом `globalThis` **годится** для функций, вызываемых из XML:
`onactivate="PMOpenOverlay()"` разрешился корректно, кнопка кликалась. То есть
`globalThis` виден обработчикам событий, но не годится для общего состояния между
файлами. Пользуемся и тем и другим осознанно: `$.PM` для модулей, `globalThis` для
точек входа из XML.

### 0.2 Компилятор CSS не проверяет цвета

Неизвестное имя цвета компилируется без единого слова. В игре это выходит
предупреждением на каждое свойство:

```
[Panorama] ***** Parsing warning on panorama/styles/postmortem/pm_button.css(1):
  Invalid value for property 'background-color': color-orange
```

Панель при этом рисуется, просто без цвета, и это легко принять за «мод не работает».
В сборке 1 так уехало четыре токена: `color-orange` дважды, `color-blue`,
`color-black&CC`. Ни одного из них в палитре игры нет.

Теперь ловится на этапе сборки: `tools/check_css_palette.py` против
`tools/deadlock_palette.txt`.

Реальная палитра — `citadel_base_styles.css`: `offWhite #FFEFD7`,
`offBlack #10130D`, `colorGold #FFED79`, `colorEnemy #FF410D`, `#FF9900`, `#5FE6A2`.
Всего 219 токенов.

### 0.3 Исключение в `boot()` не даёт ни одной строки лога

Раньше `boot()` не был обёрнут, и падение на проверке совместимости давало только
`Skipping rest of script` без указания модуля. Теперь `boot()` в `try/catch`, каждый
выход логирует, а первая строка всегда печатает, какие модули зарегистрировались.
Ожидаемый вид при успешной загрузке:

```
[PM] core loaded, compat=ok net=ok probe=ok
[PM] boot context=CitadelPostGameNew type=CitadelPostGameNew
[PM] compat host=post_game ok=true present=11 optional-absent[MVPScreen]
[PM] overlay room check: context 1920x1080
[PM] ready: host=post_game probe=loaded
```

### 0.4 Мод обязан быть видим всегда, а не появляться никогда

Сборка 3 перевела видимость кнопки под управлением JS: в XML стояло
`style="visibility: collapse;"`, а скрипт `boot()` её снимал. Результат: кнопка пропала вовсе, и
пользователь решил «мод не стоит вовсе», хотя он установлен. Это
худше от сборки 1, где кнопка была видима только за счёт ванилового CSS.

Начинаем принцип **fail-open**:

- кнопка видима всегда без условий, не только через `boot()`;
- несовместимость телить есть `PM.Compat` или `PM.Data`;
- если что-то сломалось — список проблем показать его внутри экрана.

Классические проверки теперь не гашить: она добавляются к найим значениям
`FATAL ERROR`, которые нельзя убрать в общем виде модали. Несовместимость
следует только недостаток ресурсов для версии разреза.

### 0.5 Кнопка не должна зависеть от состояния игры

В сборке 1 CSS привязывал видимость кнопки к
`.ProgressState_None` / `.ProgressState_Completed`. Это имя ваного класса, который Valve может переименовать
в любом патче, и тогда второй способ исчеззенный причины видимым и так и
не появлялся. Теперь подшай назнак и привет своей палитры.

## 1. Механика поломки

C++ ищет потомков переопределённого layout-файла **по имени**. Если нужного потомка нет,
игра падает на запуске экрана с сообщением:

```
FATAL ERROR: Unable to find child 'Team1Screen' in layout file
'panorama\layout\post_game\citadel_db_page_post_game_new.xml'
```

Два способа это вызвать:

1. **Мод вырезал ванильного потомка.** Классика. Мы так не делаем: обе правки аддитивные,
   ванильное дерево сохранено целиком, включая `MoviePanel id="PlayButtonFX"` внутри
   `PlayAgainButton`. Замечено у модов, которые убирали лишние строки «на свой вкус».
2. **Valve добавил новый обязательный потомок,** а мод грузит прошлую копию файла. Это
   наш основной риск и его нельзя исключить заранее.

Способ 2 необратим в рантайме: к моменту, когда игра ищет потомка, наш layout уже
прочитан. Поэтому единственная защита — **обновлять копию быстро** и проверять
совместимость до релиза.

## 3. Открытый вопрос про MVPScreen

Стиль `citadel_db_page_post_game_new.vcss` содержит правило `#MVPScreen`, которого нет
ни в layout-файле, ни в дампе GameTracking, ни в строковой таблице скомпилированного
`vxml_c` на сборке 25763945. То есть правило — рудимент от прошлой версии.

**Риск:** если Valve вернёт панель MVP, наша копия без неё станет недостающей и даст
`FATAL ERROR: Unable to find child 'MVPScreen'`.

`pm_compat.js` проверяет `MVPScreen` как **опциональный** и сообщает о нём:

```
[PM] compat ok=true present=11 optional-absent[MVPScreen]
```

Если появится `optional-absent[]` пустым при появлении MVP — срочно добавлять панель.
Это ровно та строка, за которой нужно следить после каждого патча.

## 3a. Суффикс `_c` в `<include>`: оба варианта работают

Ванильные скомпилированные layout-файлы игры ссылаются на стили **без** суффикса:

```
panorama/styles/citadel_base_styles.vcss
```

а уже установленный аддон QOL Lock (pak01, 2261 файлов) использует оба вида: в
большинстве своих layout — `.vcss` без суффикса, но `citadel_db_page_profile.vxml_c`
использует `.vcss_c`.

Вывод: движок резолвит оба. Опубликованный мод Commend Everyone Button, переопределяющий
тот же файл пост-матча, использует `_c` сплошным потоком, и он в каталоге с реальными
установками.

Здесь выбран `_c` повсюду — единообразно и явно, по образцу работающего мода. Если после
обновления движка резолвинг изменится, первое, что стоит попробовать — убрать `_c`.

## 4. Отсутствующий в игре ассет

Ванильный layout содержит:

```xml
<MoviePanel id="PlayButtonFX" src="file://{resources}/videos/pick_screen/play_btn_grn_flame.webm" ... />
```

**Файла нет ни в одном VPK игры** на сборке 25763945 — проверено по всем 339 VPK в
`game\citadel` и `game\core`. Игра это терпит: `MoviePanel` с отсутствующим источником
просто не проигрывает анимацию, и это текущее поведение у всех игроков.

Компилятор не терпит:

```
RESOURCE COMPILE ERROR: File does not exist "panorama/videos/pick_screen/play_btn_grn_flame.webm"
```

Из-за этого переопределить post-game layout было невозможно, пока
`tools\seed_missing_assets.ps1` не подложил 20-байтовую заглушку в
`content\citadel\panorama\...` и `game\citadel\panorama\...` CSDK.

Заглушка намеренно **вне** аддона, поэтому в VPK не попадает. Дополнительно
`build_mod.ps1` вычищает любые `.webm` из набора для упаковки.

Если Valve вернёт видео — заглушки можно удалить, компиляция будет работать и без них.

| Кнопка POSTMORTEM пропала | наш layout не попал в сборку | пересобрать, проверить `verify` |
| Кнопка есть, экран не открывается | оверлей негде рисовать или не прошла проверка совместимости | строка `overlay room check` в логе |
| Кнопка на пост-матче не видна, футер виден | игра переименовала состояния прогресса, скрывающие футер | см. `pm_button.vcss`, селекторы `ProgressState_None` / `ProgressState_Completed` |
| Вместо экрана ошибка загрузки матча | потерян `AsyncDataPanel` | аддитивное нарушение, откат |

## 6. Процедура обновления

1. Обновить игру в Steam.
2. `python tools\extract_vanilla.py --all --canary` — посмотреть, что изменилось.
   Учтите: инструмент отдаёт фрагменты строк, а не целые идентификаторы, поэтому
   `not resolved` ничего не доказывает. Он — подсказка, а не доказательство.
3. Сверить распакованный layout из GameTracking с текущей сборкой.
4. Прогнать `tools\build_mod.ps1 -Clean`.
5. Сыграть матч и пройти `docs\RUNBOOK.md`.

## 7. Отложено: вход через футер дашборда

`citadel_dashboard_footer_bar.xml` — пятая панель команд, пустая в ванильном файле,
выглядит идеальным местом для кнопки. Не используется, потому что корень
`CitadelFooterBar` имеет `height: 28px`, а оверлей строится через `$.CreatePanel` внутри
XML-контекста хоста: панель во весь экран внутри 28-пиксельного корня не отрендерится
корректно.

Чтобы вернуть этот вход, нужно одно из двух, и оба требуют замера в игре:

- измерить фактический `actuallayoutwidth/height` оверлея внутри футера и проверить,
  обрезает ли Panorama потомка по границам родителя по умолчанию;
- либо переносить оверлей в полноэкранную `DashboardPage`, что потребует третьего
  переопределения layout ради одного контейнера.

Пока не измерено — не делать. Лишнее переопределение это ещё одна поверхность
совместимости, которая ломается на каждом патче.

## 8. Аварийный откат

Пост-матч экран перестал открываться:

1. DMM → Mods Library → **Disable all mods** → перезапуск игры.
2. Если заработало — читать лог, искать `[PM]` строки.
3. Если мод нужен отключённым постоянно: в `pm_core.js` остановить `boot()` на этапе
   `verdict.ok` — кнопка останется скрытой, layout будет ванильным. Это мягче снятия:
   переопределение остаётся, но ничего не добавляет.
